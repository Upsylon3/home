# Contributing

Keep changes focused and easy to review.

- Make the smallest change that solves the problem.
- Do not commit secrets, local databases or generated build output.
- Keep application boundaries intact.
- Add or update tests for behavior changes.
- Run `npm test` before submitting changes.
- Update docs when setup or user-facing behavior actually changes.

For architecture changes, document the new boundary and its reason rather than
keeping the reasoning only in a temporary planning document.
